# 制作工作流与确认门

## 建议目录

在用户项目内沿用现有结构；新建项目时可采用：

```text
script/          锁定剧本和版本说明
shots/           分镜计划或清单
prompts/         每镜头独立提示词
assets/          定妆、场景、首尾帧参考
tasks/           API 任务 ID、请求摘要、响应状态
output/raw/      模型原始输出，只读保留
output/review/   联系表、问题帧、短测试
output/edit/     粗剪、配音版、字幕版、口型版
audio/           原始配音、音效、混音
subtitles/       ASS/SRT 及时间轴来源
```

不要覆盖原片；每次派生输出带版本或用途后缀。

## 阶段 1：需求与剧本锁定

先确认目标平台、比例、目标时长、语言、人物数量、风格、必须保留的台词和预算上限。若用户尚未确定，先交付剧本或分镜草案，不调用生成模型。

剧本至少包括：角色、逐句台词、动作、情绪、预计时间段、笑点/转折和结尾停留。用户确认后保存为版本化源文件，并在分镜、配音和字幕中引用同一份文本。

确认门：用户明确认可剧本表达和完整台词。

## 阶段 2：分镜与一致性设计

建立角色/场景基准：年龄与外观、服装、左右站位、道具、时间、灯光和画面风格。优先用一张清晰的双人定妆/场景参考图贯穿相邻镜头。

每个镜头记录稳定 ID、目标时长、出现角色、台词、动作、景别、运镜、参考素材、提示词文件、计划尝试次数和后期说明。让对白长度决定镜头总时长；必要时拆成反应镜头、物件特写或补镜，不删已锁台词。

确认门：用户认可分镜数量、镜头内容和预计成片时长。

## 阶段 3：成本与生成

实时核对目标模型的分辨率、比例、时长、参考素材限制、并发、输出有效期和价格。万相 3.0 参考视频模式的输入视频和输出视频都计费；只传图片或音频时按成功输出视频时长计费。费用按候选素材计算：

`候选计费秒数 = Σ((输出时长 + 参考视频输入时长) × 计划尝试次数)`

额外把参考图生成、重试、配音、口型同步和放大等列为单独项目。可用：

先复制模板并填入已核实的正数单价，再运行估算。模板不预填价格，避免把旧价格当成现价：

```bash
python scripts/estimate_budget.py assets/my-shot-plan.json
```

百炼万相 3.0 使用 `scripts/bailian_video.py`：先 `preview` 查看模型、地域、参数和单次费用，再通过 `submit` 对单镜提交。提交命令必须带 `--max-cost` 与 `--confirm`；未核实价格、费用超过上限、任务记录重名或缺少 API Key 时拒绝提交。每次请求不自动重试；网络超时后先去控制台核实是否已创建任务。任务 ID 保存于 `tasks/`，成功后立即轮询并下载视频，因为任务状态和视频 URL 均只保留 24 小时。其他模型须先核对官方接口，不能直接复用此客户端。

常用命令：

```bash
python scripts/estimate_budget.py assets/my-shot-plan.json
python scripts/bailian_video.py preview assets/my-shot-plan.json --shot-id shot-01
python scripts/bailian_video.py submit assets/my-shot-plan.json --shot-id shot-01 --max-cost 3.00 --confirm
python scripts/bailian_video.py poll tasks/shot-01-attempt-01.json --watch
```

API Key 从 `DASHSCOPE_API_KEY` 环境变量读取；Workspace ID 可在计划内填写或通过 `DASHSCOPE_WORKSPACE_ID` 设置。具体字段与地域配置见 [bailian-video.md](bailian-video.md)。

已批准多个镜头时也默认逐镜提交：当前镜头成功、下载落盘并能完整解码后，才提交下一镜。遇到 `AccessDenied`、`Unpurchased`、余额/额度不足或模型不可用时，停止剩余任务并报告本次是否创建任务、是否可能计费；只有用户明确要求重试后才重试该镜头。

确认门：用户认可样片和本轮预算，并明确同意付费提交。

## 阶段 4：原片审查与粗剪

逐镜检查：身份/服装/位置、换脸、五官、手部、道具、背景跳变、可读乱码、水印、动作连续性和首尾帧。联系表适合快速筛查，但可疑位置和最后 0.2–0.5 秒要逐帧检查。

无法接受的问题优先用本地裁剪、遮挡、切反应镜头或后期叠加修复；只有内容本身不可用时才重生成。先输出无字幕、无口型二次处理的干净粗剪，作为后续回退基线。

## 阶段 5：配音、字幕和混音

从锁定剧本生成或录制配音，保留自然停顿。若云端语音无权限或失败，停止重复调用并说明；可在用户接受后改用本地 TTS 或临时配音。

跨镜切分时，先用波形或静音检测缩小范围，再输出相隔 0.05–0.20 秒的候选片段进行语义试听。锁定一个切点 `T` 后，前镜结束和后镜开始都使用 `T`；补齐目标时长的静音只能加在切片之后，不能改变这个边界。

若视频模型接收了参考音频，生成结果仍可能重定时、截断或漏词。烧字幕前从最终采用的视频中提取实际音轨，以该音轨的发声段和人工试听校准字幕；不要直接沿用输入参考音频的计划时间。音频中不存在的句子应删除对应字幕并记录内容偏差。

字幕由本地 ASS/SRT 烧录或封装，不让视频模型生成。检查中文字体、换行、安全区、描边、样式一致性和音量；除非用户明确要求，不为结尾或笑点擅自改变颜色、字号或强调样式。

若音轨长于画面，应补足画面或合理延长可延长镜头；不要把自然对白压成不清晰的高速语音。

## 阶段 6：可选口型同步

先从代表性镜头裁出 3–5 秒：包含说话起止、转头和静默者。单独保留清洁视频、驱动音频、参考脸和模型输出。

双人镜头若需逐人处理，多遍推理可能累积画质损失和运动抖动。测试后同时比较原片、第一遍和最终遍；一旦出现明显掉帧、动作不连贯、换脸或嘴部异常，就停止扩展到全片，并保留未经口型处理的主版本。

确认门：用户明确接受短样片的运动连续性和画质，才处理剩余镜头。

## 阶段 7：最终验收

技术检查：时长、分辨率、比例、帧率、编码、音轨、文件可播放和文件大小。

视觉检查：完整观看加关键帧或逐帧检查；人物、服装、场景、字幕、末帧、手部/五官和跳切。

听觉检查：角色可辨识、对白清楚、停顿自然、无削波、音效不盖人声、音画同步。

分段 MP4 直接流复制拼接时要检查 `Non-monotonic DTS` 等时间戳警告。若警告来自 AAC 边界，可保留视频码流、重新编码整条音轨并用异步重采样归零时间轴；随后必须完整解码并试听所有切点。

内容检查：台词与锁定剧本逐句一致，镜头顺序、梗点、结尾和平台 AI 标识需求无遗漏。

平台上传、压缩后观感、账号权限和审核结果只有在实际平台验证后才能标记为通过。
