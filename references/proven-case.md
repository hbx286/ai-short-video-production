# 真实案例：求职“不烧心”竖屏短剧

此案例用于解释决策和止损边界，不把当时的模型价格或 API 能力视为当前事实。

## 实际结果

- 题材先经过多轮剧本修正，最终锁定两名男性在公寓餐桌旁、一本正经讲“规矩”的冷幽默对白。
- 分镜设计为 6 个镜头；生成素材为 720×1280、30fps，并用统一双人定妆参考图维持角色、服装、场景和左右位置。
- 初期为了控制费用只生成 4 个五秒镜头，但完整台词自然配音接近 30 秒。把台词压缩到约 20 秒会破坏用户已确认的文案，因此改为补生成镜头 5、6，而不是删台词。
- 某镜头只在约 4.90 秒后的最后 3 帧出现乱码。联系表未能直接定位，逐帧检查后将该段裁到 4.87 秒，保留了此前正常画面。
- 云端 Qwen 语音模型返回 `AccessDenied`。没有反复提交，而是说明权限问题后改用用户接受的 Windows 本地中文男声；实际音轨为 33.84 秒，再依据书签和静音区间制作字幕与镜头节奏。
- 最终主版本为约 33.83 秒、6 镜头、720×1280、30fps，包含双角色配音、中文字幕和轻提示音。
- VideoRetalk 对第一个 3.97 秒双人镜头做了两遍逐人口型同步。抽帧未见明显换脸，但完整观看发现动作连贯性下降、明显掉帧，因此没有扩展到全片，并保留原始主版本和测试版。

## 形成的规则

- 剧本确认必须早于付费画面生成；用户确认的原台词不能为了适配已买素材而被擅自缩短。
- 成本按候选素材而不是最终成片秒数计算；少做一个镜头可能导致后续为时长补生成，未必更省。
- 视频模型不生成可读文字；末帧也要逐帧检查。
- 配音先自然，再让画面匹配音频。权限失败时停止重试并显式告知替代音色会更机械。
- 抽帧正常不代表运动正常。口型同步和插帧类处理必须完整播放审查。
- 双人口型的多遍处理会累积损失；只从短样片开始，并把原片作为始终可回退的主版本。

## 后续音画一体迭代

同一项目后续改为把用户确认的 Qwen 母带逐镜切片，与双人参考图一并作为 Wan3.0 的 `reference_audio` 输入，一次生成画面、动作、声音和口型。该轮形成了更具体的音频经验：

- 分镜五与六的边界位于连续短语内部。仅凭静音区间多次判断错误，最后通过 0.1 秒递增候选试听锁定 24.90 秒，并让两镜共用该唯一切点。
- 视频模型输出音轨相对参考音频出现偏移和内容缺失。按参考音频制作的字幕因此错位；改为提取最终 MP4 音轨、查看发声段并结合用户试听反馈重新定时。音轨没有说出的“节奏稳了再说”从字幕中删除。
- 多镜付费任务逐镜提交。分镜六首次返回 `AccessDenied.Unpurchased` 时立即停止且未创建任务；用户明确要求重试后才再次提交并成功，避免重复账单。
- 分镜一的嘶声同时存在于模型输出和参考音频，直接换轨无效。先制作轻度/较强降噪 A/B，再只对用户指出的 2–3 秒加强频谱处理，减少整段人声劣化。
- 六段字幕 MP4 流复制拼接时出现 AAC `Non-monotonic DTS`。最终保留视频码流，仅重编码整条音轨并用异步重采样归零，随后完成全片解码、联系表和末帧检查。

这些结果说明：参考音频能显著改善一次生成的口型和表演方向，但不能替代最终音轨验收；语义试听、输出音轨字幕校准、可回退降噪和音频时间戳修复应成为标准后期步骤。
